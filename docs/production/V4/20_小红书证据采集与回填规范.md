# 小红书公开图证据采集与回填规范

更新时间：2026-09-25

## 目的

小红书上存在大量《肥鹅美食街》玩家攻略、经营菜单、实机截图和参数记录。V4 将其作为公开证据补充通道，重点服务：

- P0-A：经营日菜单、订单、食材与完整性说明。
- P0-B：Producer / Recipe / Cookware 精确参数。
- P0-C：界面信息架构、状态与入口关系的交叉验证。

小红书不是“看见一张图就抄数据”的快捷来源。所有回填仍遵循 `AGENTS.md`：证据与开发推导严格分层，无证据值保持 `null / UNRESOLVED`。

## 当前访问现实

公开搜索引擎对小红书笔记正文和图片的索引覆盖较弱。2026-09-25 的网页侧检索可以确认平台存在搜索入口，但无法稳定枚举《肥鹅美食街》相关笔记。

因此：

1. 网页搜索不到，不等于小红书没有资料。
2. 搜索引擎命中的标题、分享口令或短链只作为“候选线索”，不能直接当字段证据。
3. 需要通过小红书 App 搜索、用户提供的分享链接、公开可访问笔记页或与其他公开来源交叉验证后，再进入正式证据层。
4. 不允许为了补齐数据，根据模糊缩略图、搜索摘要或无法放大的图片猜值。

## 证据分级

### PUBLIC_IMAGE_XHS
适用：公开图文笔记中的清晰实机截图。

最低元数据：
- platform = XIAOHONGSHU
- note_title
- author/display_name（若公开可见）
- share_url 或稳定 note_id
- posted_at（可见时）
- observed_at
- image_index / image_count
- target_day / target_system
- extracted_fact
- confidence
- transcription_status

### PUBLIC_VIDEO_XHS
适用：公开实机视频笔记。

除上述元数据外必须保存：
- timestamp_sec
- frame_role
- 是否连续操作可确认因果

### PLAYER_REPORT_XHS
适用：玩家文字明确记录数值，但没有同时可见实机界面。

只可用于：
- 候选参数
- 范围锚点
- 版本敏感观察

不能覆盖更高等级的官方/清晰实机证据。

## 采集顺序

### P0-A 经营菜单
按以下优先级搜索：
1. “肥鹅美食街 + 第XX天 + 菜单”
2. “肥鹅美食街 + XX天 + 经营菜单”
3. “肥鹅美食街 + XX天 + 菜谱”
4. “肥鹅美食街 + XX天 + 食材”
5. 同作者主页连续经营日笔记

优先目标见：
`research-data/levels/xiaohongshu_source_hunt.csv`

发现笔记后先判断：
- 是菜单图、食材图还是玩法截图；
- 作者是否明确“完整/没漏/只有这些/少一张”等；
- 图片数是否等于订单数：默认 **否**；
- 是否能读清每个要求项；
- 同一天是否存在版本差异。

只有完成这些判断后才能写入 `order_registry_110.*`。

### P0-B Producer / Recipe / Cookware
搜索组合：
- 发射器 + 等级 / 升级 / 冷却 / 次数 / 掉落 / 产出
- 厨具 + 烹饪时间 / 队列 / 加速
- 菜谱 + 食材 / 厨具 / 时间
- 具体 Producer / Cookware 名称 + “几次”“分钟”“秒”“概率”

Producer 数值最低要求：
- Producer身份可确认；
- 等级可确认；
- capacity/cooldown/output 等字段对应的是该等级；
- 如为概率，必须有足够样本或官方明确说明；单次截图不能推导权重。

Recipe/Cookware 数值最低要求：
- 输入项清楚；
- 使用厨具清楚；
- 倒计时或时长清楚；
- 输出物清楚；
- speedup 若记录，必须明确其单位和时点。

## 图片与版权

仓库目标是研究证据与原创产品生产，不是建立原作素材镜像。

默认做法：
- 保存公开来源 URL、元数据、转录文本和字段事实；
- 不批量提交原作完整高清图片；
- 需要留图证时优先记录公开 URL、图片序号和哈希/描述；
- V4 正式美术仍必须原创。

## 与现有来源交叉验证

小红书主要用于补强，不替代已有高质量来源。

现有锚点：
- Day11-20：TapTap 公开图片。
- Day51-60：抖音公开视频。
- Day82-94、98-99、106-110：TapTap 公开帖子/图片。
- App Store 编辑页公开确认：升级发射器可提高产出效率；“爆炒时刻/爆炒接力”期间烹饪加快，相关发射器与厨具进入无限供应状态。
- 游茶科技实机拆解公开确认：“爆炒时刻”通过完成订单积累火苗，达到目标后在限时窗口内使相关生成器拥有无限发射次数。

当小红书与其他来源冲突时：
1. 记录 observedAt / channel / 游戏版本；
2. 不直接覆盖旧值；
3. 将冲突标为 VERSION_SENSITIVE 或 CONFLICTING_EVIDENCE；
4. 需要更多实机证据后再决定 Runtime 使用值。

## 回填门禁

每次把小红书证据写入生产数据后必须运行：

```powershell
npm run audit:data
npm run audit:evidence
npm run audit:content
npm run audit:runtime
```

涉及可运行配置时再运行：

```powershell
npm run validate:config -- production-data/v4/runtime/game_content.json
npm run simulate:balance -- production-data/v4/runtime/game_content.json
```
