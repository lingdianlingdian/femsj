# V4 美术素材并行生产与首批任务

更新时间：2026-09-25

## 目标

美术不再等待策划、数值和代码全部结束后再开始，而是与当前 V4 Production Bible 并行推进。所有正式资产仍遵守 `AGENTS.md`：先有 AssetId，再出图；公开截图只作为研究证据，不复制竞品角色、UI皮肤、图标、建筑或文案。

## 三层工作流

### A. 公开视觉参考层
只记录稳定公开链接、界面信息层级、可读性、视角、轮廓密度、状态表达和构图观察。
- TapTap / 官方商店 / 公开视频 / 小红书公开帖只进入 research-data。
- 不把第三方截图作为正式游戏资源。
- 小红书继续按 `20_小红书证据采集与回填规范.md` 采集；能确认结构的内容回填 `research-data`，不能稳定访问的只记录检索词与待采状态。

### B. 原创 Style Anchor 层
先锁定 14 个 Anchor：UI、棋盘、Item、Dish、Producer、Cookware、角色、建筑、环境物和 VFX。Anchor 通过后才允许同族批量生成，避免不同模型、不同轮次造成风格漂移。

### C. 正式资产层
先服务可运行 Day1-10 垂直切片，再扩展 110 日全量：
1. Core UI / Board；
2. Day1-10 Item / Dish；
3. 4 个早期 Producer + 1 个 Cookware；
4. 店长柚宁、引导鹅团团、首位主要顾客小满；
5. Street01 首个建筑 Before/After + 首批环境物；
6. Merge / Producer / Cook / Reward / Build VFX。

## 原创视觉基线

与现有 Design Token 同源：
- 背景：#FFF7E8
- Surface：#FFFDF8
- 主色：#F6A43A
- 绿色强调：#78C65A
- 能量蓝：#49B9F2
- 金币黄：#F5C84C
- 宝石粉红：#EF5471
- 深暖描边：#543C2F / #76543A

统一风格：
- 治愈、明亮、温暖、街坊感；
- 2D 手绘 + 轻体积，不做摄影写实；
- 食物 15°–30° 俯视，左上主光，软阴影；
- 角色采用原创比例与配饰，不复刻竞品具体肥鹅脸型、服装或轮廓；
- 建筑走原创“中国社区美食街”方向，不复刻竞品店铺；
- UI 只借鉴信息层级和交互关系，不进行像素级复现。

## AI 生成资产执行规则

正式生成任务由 `ai_art_jobs_v4.json` 驱动。每个 Job 必须包含：
- job_id；
- asset_id / anchor_id；
- 类别；
- source_size；
- transparent；
- prompt_spec；
- forbidden；
- output_contract；
- acceptance_gate。

禁止提示词包含“照着某游戏一模一样”“复刻某截图”“与原作完全一致”等要求。

## 生产状态

统一状态：
`PLANNED -> READY_FOR_CONCEPT -> CONCEPT_REVIEW -> CANON_LOCKED -> GENERATED -> CLEANUP -> QA -> APPROVED -> INTEGRATED`

只有 `APPROVED` 才允许同步回 `assets_master.csv` 的正式状态；只有 `INTEGRATED` 才算进入 Cocos 资源树。

## 验收门禁

每个正式资产必须检查：
1. Canon；
2. Readability；
3. Perspective；
4. Palette；
5. Outline；
6. Lighting；
7. Scale；
8. Bundle；
9. Performance；
10. Copyright/originality。

Item 额外做 64×64 缩略测试；角色额外做固定配饰/喙/眼距/头身比一致性；建筑额外做 Before/After Pivot 与 Bounding Box 偏差测试。

## 并行协作约定

- 代码/数值 Agent 可继续修改 runtime、balance、P0-B，不需要等待美术。
- 美术线程只新增或更新 `production-data/v4/art/`、角色 Canon 产物和 Street 视觉资产，不改数值语义。
- 任何内容 ID 变更必须由数据层先落稳定 ID，美术随后改引用，禁止美术自行改 ContentId。
- 其他 Agent 如需占位图，只引用 AssetId，不创建“临时最终图”。
