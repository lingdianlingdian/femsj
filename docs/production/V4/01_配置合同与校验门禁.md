# V4 配置合同与校验门禁

V3 的 Schema 只验证“数组存在”，V4 改为字段级合同。

## 必须通过的静态检查

1. 所有 ID 符合小写稳定 ID 规范。
2. Order 引用的 Item / Producer / Recipe / Cookware 必须存在。
3. Recipe 输入必须可达，输出 Item 必须存在。
4. Transformation Graph 不允许无出口死循环。
5. Producer outputPool 权重必须 >0，构建时归一化并输出实际概率。
6. Day 的 orderIds 必须与 order.day 一致。
7. BuildNode prerequisite 不允许环。
8. 普通 Order 的 difficulty 同时出现高体力+高等待+高冷却时 CI 失败。
9. Event 必须有结算规则，限时奖励不得因入口消失而吞失。
10. 公开证据与开发推导必须都保存 evidence 字段。

## Evidence

`evidence.kind=DEV_BLUEPRINT` 的数据允许进入原创项目，但不得在研究报告中表述为“原作精确数值”。

## 版本

正式配置由：

```text
configVersion
contentRevision
validFrom
validTo
channelOverrides
```

共同管理。运营参数不写死在客户端。
