# P0-B 参数证据门禁

更新时间：2026-09-25

## 目标

`research-data/evidence/p0b_parameter_evidence_matrix_v4.csv` 是 Producer / Cookware / Recipe 精确参数进入 Runtime 前的证据门禁。

它解决一个核心问题：**“确认机制存在”不等于“已经拿到可运行精确数值”。**

例如：
- 玩家/实机已证明发射器会耗尽并进入等待，不代表已经知道 `capacity` 或 `cooldownSec`。
- 玩家说“做个菜四十几分钟”，只能证明某版本存在长烹饪等待；未绑定菜谱/厨具时，禁止把 40 分钟写给任何具体 Recipe。
- Apple App Store 编辑推荐确认升级发射器能提高产出效率、爆炒期间烹饪加快和相关发射器/厨具无限量供应，但没有给出升级曲线、倍率、容量或秒数，因此仍不能用于精确 Balance 参数。

## status

### EVIDENCED_EXACT

字段级数值已经由清晰公开实机图绑定到具体实体，可用于证据支持的生产配置。仍只能使用证据明确支持的字段；例如 durationSec 已确认，不代表 speedup、queueSize 或 cookware 等其他字段同时确认。

### EVIDENCED_RELATION / EVIDENCED_OUTPUT_RELATION

关系本身可进入内容图或 Runtime 内容引用，例如：
- 饮料柜 → 能量饮料
- 饮料柜 → 香槟
- 肉肠 + 烤架 → 烤肠
- 蘑菇 + 洋葱 + 芝士片 + 备菜台 → 菌香芝士卷

这不自动证明概率、时长或资源消耗。

### EVIDENCED_MECHANISM

机制确认存在，但没有足够精度直接成为数值配置，例如：
- Producer 冷却存在
- 烹饪等待存在
- 爆炒时刻存在速度/供应增强
- 升级 Producer 能提升产出效率

### EVIDENCED_VERSION_SENSITIVE

玩家在特定版本/渠道明确观察到的事实。必须保留版本/时间语境，不能直接写成永久规则。

### OBSERVED_UNBOUND

观察值存在，但无法绑定到具体实体。只能用于研究搜索和测试边界，不能回填生产配置。

### UNRESOLVED_EXACT

Runtime 需要该精确字段，但目前没有可审计证据。必须保持 `null / UNRESOLVED`，或在独立原创垂直切片中明确标 `DEV_BLUEPRINT`。

## runtime_usable

只有 `runtime_usable=true` 的事实才允许直接进入“原作证据支持”的运行内容。

即使 `runtime_usable=true`，也只能使用这一行明确支持的字段：
- 已证明 output relation，不能顺带填 weight。
- 已证明 cookware relation，不能顺带填 duration。
- 已证明活动加速存在，不能顺带填 multiplier。

## 小红书采集优先级

小红书优先寻找以下类型截图：

1. **发射器详情/升级界面**
   - 必须同时能看到名称、等级和待测参数。
2. **发射器从满状态连续点击到耗尽的视频/连图**
   - 用于 capacity。
3. **耗尽后出现冷却倒计时的截图**
   - 用于 cooldownSec。
4. **同等级大量连续产出的录屏**
   - 用于 outputWeight；单次截图不够。
5. **厨具倒计时面板**
   - 必须同时识别输入、厨具、输出/菜名。
6. **加速弹窗**
   - 同时记录剩余秒数与钻石价格，才能推 speedup。

发现小红书笔记后先登记来源，不直接覆盖生产表。证据通过后再回填 `production-data/v4/content/*`。

## 与 Codex 协作

- Codex 的 Day1-10 原创垂直切片可以继续使用明确标记为 `DEV_BLUEPRINT` 的开发默认参数。
- 原作研究参数不得因为垂直切片“需要数值”而被反向伪填。
- Balance Simulator v3 同时支持开发调参与未来 evidence-backed 配置，两层必须保持可区分。
