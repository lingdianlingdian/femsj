# 《肥鹅美食街》全美术规格书 V3

> 本文是**原创同类项目的生产规范**，不是原作内部源文件尺寸。  
> 公开资料只能观察到画风、界面结构和视觉层级；下列像素尺寸、分层方式、命名和导出规则是为了让 Cocos 项目可量产而制定。

# 1. 美术方向

公开官方描述强调“治愈画风、市井人情、Q萌肥鹅、美食烹饪”。公开实机图表现为：
- 明亮暖色；
- 高饱和食物；
- 粗而柔和的轮廓；
- 物品体积感偏 2D 手绘/轻伪3D；
- UI 大圆角、大按钮；
- 资源和订单优先于背景装饰；
- 场景从冷清/破败逐渐变热闹。[S01][S02]

原创项目可以学习“可读性与情绪”，但角色造型、店铺、图标、剧情、美术细节必须重新设计。

# 2. 分辨率体系

## 2.1 UI
- 逻辑基准：750×1334。
- UI源文件：建议按逻辑尺寸 2× 绘制，即 1500×2668。
- 极大背景可按 1×~1.5×，避免小游戏包体爆炸。
- 小图标至少提供原始 256×256 或以上。

## 2.2 世界/主街
- 单屏可见基准：750×1334。
- 世界背景允许横向 2~4 屏。
- 分层：Far / Mid / Building / Prop / NPC / FX / HitArea。
- 不允许把整条街烘焙成一张超大 PNG。

# 3. 棋盘规格

## 3.1 Board
- 9列×7行。
- 推荐棋盘可视宽：684。
- Cell：76×76 逻辑像素。
- Cell边框占用≤4px。
- Item实际主体建议占 Cell 的 84%~92%。

## 3.2 Item 图
源文件：
- 普通食材：256×256；
- 高阶食材/菜：320×320；
- 生成器：384×384；
- 厨具：384×384。

运行时在盘面统一缩放到 60~72 逻辑像素主体范围。

### 每张 Item 必须有
- `icon`;
- `shadow`（可共用）；
- `locked_silhouette`（可运行时灰化，不必重复出图）；
- 稀有/活动角标（组件化，不烘焙进图）。

# 4. 合成链画法

同一链必须遵守：
- 等级越高，轮廓面积/装饰复杂度上升；
- 主色保持家族一致；
- Lv1~Lv3 一眼可看出同源；
- 不要只靠“加更多小装饰”区分高阶；
- 高阶菜的视觉焦点应是成品，不是碗盘占 70%。

### 辨识测试
把 20 个 item 缩到 64×64：
- 玩家 1 秒内能区分 80%以上；
- 同链相邻等级不能只差一个难以辨识的小零件。

# 5. 食物图标

建议：
- 视角：约 15°~30° 俯视；
- 主光：左上；
- 轮廓：深暖色，不用纯黑；
- 阴影：软边；
- 高光：集中在食物湿润/瓷器区域；
- 背景透明。

禁止：
- 摄影写实；
- 过度材质噪声；
- 细线过多；
- 复杂文字贴在食物上。

# 6. Producer

每个 Producer 至少需要：
1. Normal；
2. Ready；
3. Tap/Press；
4. Cooldown；
5. Boosted；
6. Locked；
7. Upgrade highlight。

如果使用骨骼动画：
- Idle 2~4s 循环；
- Tap 0.15~0.25s；
- Exhausted 1s 后进入静态；
- Boosted 添加独立 FX，不重新画整套。

# 7. Cookware

每个厨具：
- Idle；
- InputAccepted；
- CookingLoop；
- Ready；
- Collect；
- SpeedUp。

推荐：
- CookingLoop 2~4s；
- Ready 用香气/闪光表达；
- 不要让烹饪特效覆盖剩余时间。

# 8. 顾客/肥鹅角色

## 单角色交付包
- 角色全身立绘：2048×2048；
- 半身剧情立绘：1536×1536；
- 头像：512×512；
- 小场景角色：512×512 或 Spine；
- 表情最少：正常/开心/惊讶/难过/生气/期待；
- 动作最少：Idle / Eat / Cheer / Sad / Walk。

### Spine建议
- Canvas人物骨骼数量：≤80；
- Mesh 顶点：≤2500/角色；
- 同屏 6~10 个角色时仍需保持稳定帧率。
- 不要给每个路人做高复杂 Spine，可分主角/重要顾客/普通顾客三档。

# 9. 主角

若原创项目保留“人类经营者+动物顾客”结构：
- 主角需要 3/4 身剧情立绘；
- 6~10 表情；
- 2~3 套关键剧情服装即可；
- 不建议让主角成为复杂换装系统，除非它是商业化主轴。

# 10. 建筑与主街

## BuildNode 每级资产
```text
Stage0_Ruin
Stage1_Clean
Stage2_Basic
Stage3_Decorated
Stage4_Alive
```

不一定每个建筑都五阶段，但每个重要节点至少有：
- Before；
- ConstructionMask/FX；
- After。

### 单建筑建议源尺寸
- 小摊：1024×1024；
- 中店：1536×1536；
- 地标：2048×2048；
- 远景只需与屏幕密度匹配。

### 分层
建筑不能烘成一张：
```text
base
roof
sign
awning
counter
foreground props
lights
smoke
interactive marker
```

这样可做昼夜、节日换皮和建造动画。

# 11. 场景区域

110 日生产目标建议 4 个主要区：
1. 起始街口；
2. 核心食肆区；
3. 夜市/饮品区；
4. 高阶特色区。

每区：
- 1 主背景；
- 8~15 建设节点；
- 20~40 环境小物；
- 6~12 NPC点位；
- 2~4 循环环境动画。

# 12. UI组件美术

## 通用按钮
- Primary：高饱和暖色/主题色；
- Secondary：浅底+深描边；
- Destructive：红；
- Disabled：饱和度降低 70%、对比减弱。

状态：
```text
Normal
Pressed
Disabled
Selected
Attention
```

不要为每个按钮出五张完整位图；优先 9-slice + 组件状态。

## 卡片
- 订单卡；
- 商店卡；
- 奖励卡；
- 活动卡；
- 卡册卡位。

全部使用 9-slice 背板，不要每种尺寸重画。

# 14. 稀有度体系

建议仅 4~5 档：
```text
Common
Uncommon
Rare
Epic
Legendary
```

颜色只是辅助，必须同时使用：
- 边框；
- 星级；
- 小图标/纹理；
避免纯色区分导致色弱不可读。

# 15. VFX

## 合成
0.25~0.45s：
```text
吸附
→ 压缩
→ 闪光
→ 新物弹出
```

## 生产
0.25~0.40s：
```text
Producer Bounce
→ Particle
→ Item Arc
→ Cell Land
```

## 烹饪
- Steam；
- Sparkle；
- Glow；
- Ready pulse。

## 奖励
- Coin/Gem/Energy 飞向资源栏；
- 单次粒子数受限；
- 资源飞行完成后再更新视觉数字。

## 建造
1.2~2.5s：
```text
Dust
→ cover
→ reveal
→ light/spark
→ NPC cheer
```

# 16. 动画帧率

- UI Tween：60fps 时间轴；
- Spine：30fps 关键帧即可；
- 序列帧：12~24fps；
- 大量环境动画：12fps 可接受。
- 低端机可关闭非必要环境粒子。

# 17. 纹理与压缩

微信小游戏：
- 优先 WebP/平台支持格式用于远程图片；
- Cocos Texture 默认启用合适压缩；
- UI小图集中图集；
- 超大场景分 Bundle；
- 不允许一个 Atlas > 2048×2048 在低端机无必要地堆满透明区。

推荐：
- UI Atlas：1024/2048；
- Board Item Atlas：按链拆分；
- Event Atlas：每活动独立 Bundle；
- Character：重要角色独立或小批次打包。

# 22. AI美术生产要求

如果使用生成式图像辅助：
1. 先建立 20~30 张“Style Anchor”；
2. 每条食物链固定同一视角、轮廓、光向；
3. 所有生成结果进入人工/模型二次清洗；
4. 图标必须去背景、统一描边、统一阴影；
5. 不允许把不同模型不同风格图标直接混进盘面；
6. 角色必须经过 Canon 校验，避免脸型/喙/服饰漂移。

### 资产验收模型
```text
Silhouette
Palette
Perspective
Outline
Lighting
Material
Scale
Canon
Readability@64px
```

9项全部通过再入库。

# 23. 美术验收门禁

- 64×64 仍能识别物品；
- 同链相邻等级可辨；
- Producer/普通食材不混淆；
- 厨具状态可辨；
- 所有按钮 Press/Disabled 有状态；
- 9-slice 拉伸无变形；
- 主街 20:9 不露空白；
- 低端机同屏特效不过量；
- 所有正式资源有唯一 AssetId；
- 源文件和导出物可追溯。
