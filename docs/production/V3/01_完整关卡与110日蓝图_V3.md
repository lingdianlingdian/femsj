# 《肥鹅美食街》完整关卡研究与 110 日开发蓝图 V3

> 定位：开发档，不是“伪造原作后台配置”。  
> **E-*** = 有公开资料证据；**D-BLUEPRINT** = 为了让项目可直接开发而补齐的原创/推导蓝图。  
> 所有 P50/P90 体力预算均为**开发目标值**，不是声称原作官方数值。

## 1. 关卡定义

本项目把“经营日”定义为一个可独立验收的关卡单元：

```text
Day
├─ EntryStory
├─ ActiveOrders[]
├─ Unlocks[]
├─ BuildNodes[]
├─ OptionalEventHooks[]
├─ DayReward
├─ ExitStory
└─ NextDay
```

单日设计必须同时控制 6 个维度：

1. 体力成本；
2. 生成器冷却；
3. 烹饪等待；
4. 棋盘峰值占格；
5. 手动操作次数；
6. 副产物利用率。

## 5. 每阶段设计目标

### P0｜Day 1-5：教学
- 目标：不让玩家同时学习超过 1 个新概念。
- 盘面：默认空位 ≥ 35%。
- 普通订单：1~2 个需求物。
- 禁止：高等级链 + 长冷却 + 长烹饪同时出现。
- Day5 首次让玩家明确看到“材料可以继续合成，也可以投入厨具”。

### P1｜Day 6-10：闭环建立
- 加入加工菜。
- 开始出现多个来源链组合。
- 首次出现 3 材料菜谱。
- 订单集合必须让至少 60% 的高频副产物有去处。

### P2｜Day 11-20：扩展
- 每 3~4 天只引入 1 条真正的新链。
- 新生成器首次出现的 2 天内不同时强压体力。
- 可开始开放短活动，但不允许活动抢走主线全部体力。

### P3｜Day 21-35：系统展开
- 引入订单交叉与更高阶加工。
- Day35 前后允许第一次“需要跨会话完成”的大单。
- 公共玩家反馈显示原作从约 Day35 起卡关显著，原创设计建议将这种摩擦改为“有预告的大单”，不要无提示常态化。

### P4｜Day 36-50：中期经营
- 加入海鲜/汤品/面点类生产生态。
- 开放第三种主要厨具类型。
- 建设分区要提供明显视觉变化。
- 单日至少有 1 个“低消耗快完成单”维持正反馈。

### P5｜Day 51-70：复合烹饪
- 可以加入多厨具链与高级饮品。
- 单一订单允许出现中间加工，但必须限制串行等待总时间。
- 普通单禁止：P90>300 等效体力且等待>20min 且生成器强冷却，三者同时成立。

### P6｜Day 71-90：高阶调度
- 原作公开 Day75 玩家样本中，“能量饮料+香槟”同源饮料柜，玩家估算约 700-800 体力。[S13]
- 这是高压锚点，不建议原创产品把这种强度当普通单。
- 高阶单必须有：高金币/高活动积分/明确大单视觉。
- 盘面应提供临时仓库、订单副产物吸收或短期无限生产等缓压手段。

### P7｜Day 91-110：长线终局
- 主要挑战来自“跨链调度”，而不是无限抬高单链等级。
- 110 日结束时形成阶段性结局，并预留新街区、新厨具或新顾客的下一章钩子。
- 终局内容要允许已掌握系统的玩家通过计划降低成本，而不是只有付费能绕过。

## 6. 订单组合门禁

每组并行订单生成后计算：

```text
ByproductUtilization =
可被当前订单集合消耗的高频掉落期望价值
/
全部高频掉落期望价值
```

建议：
- < 40%：禁止上线；
- 40~60%：高风险；
- 60~80%：合格；
- >80%：高度协同。

## 7. 难度向量

每个订单保存：

```json
{
  "energyP50": 0,
  "energyP90": 0,
  "cookWaitSec": 0,
  "producerBlockSec": 0,
  "peakCells": 0,
  "manualActions": 0,
  "byproductUtilization": 0
}
```

不要只保存一个“难度=5”。

## 8. 关卡验收

每一天自动模拟 10,000 次，输出：
- P50/P75/P90/P95 体力；
- 完成时长；
- 生产器冷却次数；
- 厨具等待；
- 峰值占格；
- 盘满概率；
- 副产物出售概率；
- 免费玩家需要的会话数。

### 硬门禁
- 普通日盘满概率 > 5%：失败；
- 普通订单同时满足“高体力+高等待+高冷却”：失败；
- 新系统引入当天若 P90 突增 >35%：失败；
- 活动与主线共用资源时，免费玩家完成率模拟 <50%：必须调整。
