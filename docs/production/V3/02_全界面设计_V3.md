# 《肥鹅美食街》全界面设计说明 V3

> 本文给的是**可直接交给 UI/前端/Cocos 制作**的完整页面规范。  
> 标记：**E** = 公开资料确认原作存在该类页面/功能；**R** = 为了生产完整性补齐的推荐页面；**E/R** = 原作概念可确认，但下面的布局与交互规格属于开发补全。

# 1. 设计基准

## 1.1 逻辑画布
- 基准逻辑分辨率：**750 × 1334**。
- 设计模式：竖屏。
- Canvas：`Fit Width = true`；高度按设备比例延展。
- 目标适配：16:9、18:9、19.5:9、20:9。
- 内容安全区：必须读取平台 SafeArea，不允许把体力、关闭按钮、付费确认贴进刘海/灵动岛/系统手势区。

## 1.2 纵向区域

```text
0 ─────────────────────────────
Safe Top / 平台胶囊避让
60~150   顶部资源条
150~310  订单横向区 / 活动提示
310~900  核心棋盘或主内容
900~1180 页面辅助功能
1180~1334 底部导航/手势安全区
```

不同宽高比设备只扩展“背景/场景”，**棋盘、资源条、订单卡的视觉尺寸不跟屏高无限拉伸**。

## 1.3 栅格与间距
- 基础单位：4 px。
- 常用：8 / 12 / 16 / 24 / 32 / 40 / 48。
- 页面左右安全边距：24~32。
- 弹窗内容边距：32。
- 主要按钮高度：80~92。
- 次按钮高度：64~72。
- 最小可点击热区：88×88 逻辑像素。
- 圆角：16 / 24 / 32 三档。

# 3. 核心页面逐页规格

## UI05｜9×7 合成主盘

公开截图可见：顶部经营日/体力/金币/钻石；订单卡横向排布；核心区域为 9×7 盘面，物件包括生成器、厨具、食材、奖励等。[S02]

### 结构

```text
Canvas
├─ Bg
├─ SafeTop
├─ TopResourceBar
│  ├─ DayBadge
│  ├─ EnergyChip
│  ├─ CoinChip
│  └─ GemChip
├─ OrderCarousel
│  ├─ OrderCard x N
│  └─ ScrollIndicator
├─ BoardFrame
│  └─ BoardGrid (9×7)
│     └─ Cell[63]
├─ ContextActionLayer
├─ FloatingEventButtonGroup
├─ BottomUtility
│  ├─ Storage
│  ├─ RecipeBook
│  ├─ Shop
│  └─ Home
└─ TutorialOverlay
```

### 尺寸建议
- Board 外框：684×548。
- 单格视觉：约 76×76。
- 实际点击区域：76×76，不允许图标透明区缩小热区。
- OrderCarousel：高 150~170。
- 单订单卡：宽 280~340，高 120~140。
- 顶部资源条：高 92。
- 资源 Chip：约 150×64。
- 底部工具按钮：88~96。

### 单格状态
```text
EMPTY
OCCUPIED
LOCKED
BLOCKED
HIGHLIGHT_SOURCE
HIGHLIGHT_TARGET
MERGE_TARGET
COOK_TARGET
ORDER_REQUIRED
```

### 拖拽反馈
- 抬起物件：Scale 1.00→1.08，Y 抬高 8~12px。
- 合法合并目标：目标呼吸 1.00↔1.06。
- 非法目标：0.15s 左右摇摆。
- 拖出盘外：回弹 0.18~0.24s。
- 严禁拖拽时遮住目标格高亮。

### Producer 点击
- 单击：产出一次。
- 长按 ≥250ms：进入连续产出（原创改良）。
- 满盘、0体力、冷却：先反馈原因，再决定是否弹资源入口。
- 满盘时绝不扣体力。

## UI10｜厨具加工

### 信息层级
1. 厨具名称/等级；
2. 输入槽；
3. 可做菜谱；
4. 时间；
5. 开始按钮；
6. 加速入口。

### 三态
```text
IDLE
COOKING
READY
```

COOKING 显示剩余时间和可选加速；READY 使用强视觉“可领取”，但不要全屏强弹。

## UI14｜主街

公开资料确认建设从“几乎没有顾客的废弃地”逐渐变成有烟火气的美食街，建设与剧情推进挂钩。[S02]

### 层级
```text
WorldCamera
├─ Background
├─ FarDecoration
├─ BuildableLots
├─ FinishedBuildings
├─ NPC/Geese
├─ VFX
└─ ClickHotspots

HUD
├─ ResourceBar
├─ ActivityDock
├─ Quest/BuildPrompt
└─ EnterBoard CTA
```

### 交互
- 单指拖动画面；
- 点击施工点→建设详情；
- 点击鹅→短气泡/剧情入口；
- 点击已建店铺→信息/产出/剧情（视项目设计）；
- 不要把主街做成复杂路径模拟器，核心是“进度可视化”。

## UI20｜商店

公开截图显示商店包含多列商品卡、钻石价格、剩余购买次数、刷新倒计时与付费刷新。[S13]

### 布局
- 顶部橙白遮阳棚式标题区只是原作视觉证据；原创项目可换主题。
- 三列商品网格最适合 750 宽基准。
- 商品卡建议 210×250。
- 卡内顺序：物品图→剩余次数→价格按钮。
- 刷新条固定底部：倒计时 + 刷新价格。

## UI26｜时空追逐
- 顶部活动名+剩余时间；
- 中间里程碑轨道；
- 3~8名小型竞速组；
- 玩家位置始终可见；
- 奖励节点可点击预览；
- 结束后必须有自动结算兜底。

## UI28｜爆炒时刻
- 强调“限时爽感”；
- 显示倒计时；
- 明确哪些生成器获得无限/增强；
- 进入期间棋盘上的目标生成器加统一光效边框；
- 结束前 60s、10s 各做一次非打断式提示。

## UI29｜烹调争霸赛
公开截图显示：活动弹窗有大锅主题插画、剩余时间、倍率按钮 x1/x3/x10、进度条与奖励。[S13]
- 倍率按钮必须同时显示“消耗”和“收益”变化；
- 不允许只改变成本但不解释收益；
- 活动结束自动结算。

## UI30-33｜卡册
玩家社区记录过 108 张卡、重复卡和下一轮收集。[S13]
开发建议：
- 首页按套组显示完成度；
- 卡组详情显示缺卡，不隐藏套组剩余数量；
- 重复卡必须有明确价值；
- 赛季结束前提供可控补缺机制；
- 开包动画 2~4 秒，可一键跳过；
- NEW、重复、稀有度视觉必须明显区分。

# 4. 顶部资源条规范

顺序建议：

```text
Day | Energy | Coin | Gem
```

- Day：左侧，64~76 方形徽章。
- Energy：闪电图标 + 当前值 + 恢复倒计时 + 小“+”。
- Coin/Gem：数值右对齐，小“+”。
- 数字变化：0.2s 弹跳；资源飞入完成后再更新最终数值。
- 若数值 > 99999，使用 99.9K / 1.2M，但点击可看精确值。

# 5. 订单卡组件

Prefab：
```text
OrderCard
├─ CustomerAvatar
├─ RequirementRow
│  └─ RequirementItem x 1..3
├─ RewardRow
├─ ActivityBonus
└─ CompleteState
```

状态：
- 未满足：数量 `0/1`；
- 部分满足：已拥有高亮；
- 全满足：整卡轻微高亮 + CTA；
- 提交中：锁输入；
- 已完成：奖励飞出后移除。

不要把“可提交”只靠颜色表达，要加勾/按钮态，兼容色弱。

# 6. 弹窗系统

四层：
1. `Toast`：1.5~2.5s；
2. `MiniPopup`：资源不足/确认；
3. `Modal`：商店、活动；
4. `FullScreenOverlay`：剧情、开包、重大解锁。

### 规则
- 同时只允许 1 个 Modal；
- 付费弹窗进入 2 秒内不允许再次自动弹另一个；
- 用户手动关闭限时礼包后，同一会话不重复强弹；
- 所有活动结束奖励自动入邮箱，避免“已完成未点击领取而丢失”。

# 7. 新手引导

引导不是“黑幕+手指”无限串联。

步骤模型：
```text
Trigger
→ FreezeAllowedSystems
→ FocusTarget
→ Hint
→ ExpectedAction
→ Validate
→ Release
```

必须支持：
- 跳过非核心叙事；
- 中断恢复；
- 版本迁移；
- 已完成步骤幂等。

# 8. 字体与字号

建议中文字体：项目授权的圆润黑体；不要直接依赖系统字体做核心美术。

| 用途 | 字号 |
|---|---:|
| 超大活动标题 | 42~52 |
| 页面标题 | 36~42 |
| 重要数字 | 32~40 |
| 按钮 | 28~34 |
| 正文 | 24~28 |
| 次要说明 | 20~24 |
| 倒计时/角标 | 18~22 |

正文行高：字号×1.35~1.5。

# 9. 颜色功能语义

原创产品建议：
- 金币：暖黄；
- 钻石：高饱和冷红/粉红宝石；
- 体力：天蓝；
- 可领取：高亮绿/金；
- 错误：红；
- 锁定：低饱和灰蓝；
- 活动稀有：紫/金只用于稀有度，不作为全局主色。

必须保证文字对比度，不要为了“可爱”牺牲可读性。

# 12. 状态与空态

每个列表必须设计：
- Loading；
- Empty；
- Error；
- Offline；
- Expired；
- Claimed；
- Locked。

尤其活动结束后，禁止仅“入口消失”；必须可从邮箱/结算页拿到应得奖励。

# 13. UI验收门禁

- 750×1334、750×1624 两种逻辑高都无裁切；
- iPhone 刘海/灵动岛和安卓打孔无关键按钮遮挡；
- 最小触控热区≥88×88；
- 文本放大 10% 不爆版；
- 99999999 数值不溢出；
- 订单 3 个需求物不溢出；
- 活动标题 10 中文字不爆版；
- 离线/弱网均有明确状态；
- 购买按钮重复点击只发一次请求。
