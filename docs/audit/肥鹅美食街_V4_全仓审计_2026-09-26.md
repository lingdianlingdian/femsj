## P0 / 合并阻断

### 1. PR #21 未同步 main，当前无可用 CI 结果

PR #21 head `941af4b8d93b20d38eb0e1dd36393f98466692ca`：
- ahead main 48 commits
- behind main 1 commit
- merge base 为 `446811482b9dfc651d38fb486c67459be8f5de92`
- 与 #20 路由修复发生分叉
- 当前 GitHub Actions 没有针对该 head 的有效 PR run

因此 #21 不能在未同步 main、未重新跑完整 V4 Quality Gates 前合并。

### 2. PR #21 会覆盖 #20 的路由回归门禁

main 当前：
`cocos:contracts:check = build.mjs --check && npm run cocos:routes:test`

#21 branch 当前退回：
`cocos:contracts:check = build.mjs --check`

并且缺少 `cocos:routes:test` script。

必须保留 #20 的 16 条参数化路由 + 3 条 modal 路由回归。

### 3. PR #21 BoardModel 与现有 QA 合同不一致

当前 BoardModel 是 63 格基础数组，但以下已有 QA 合同尚无法满足：
- TC_BOARD_001：移动后 `revision+1`，BoardModel 无 revision。
- TC_BOARD_007：LOCKED cell 不可放置，BoardModel 无 cell state。
- TC_BOARD_008：BLOCKED cell 不可操作，BoardModel 无 cell state。
- instanceId 唯一性未强制。调用 `spawn(..., "board_item_1")` 后，内部 `nextId()` 仍可能再次生成 `board_item_1`。

在合并前至少应补 domain-level regression，确保基础模型不会与 QA 合同相反。

## P1 / 生产化缺口

### 4. Cocos TypeScript 没有独立编译门禁

当前：
- 无 `tsconfig.json`
- 无 TypeScript compile/check script
- `ScreenRouteMatcher.ts` 使用 `@ts-nocheck`
- CI 主要验证 JSON/生成物，不验证 Cocos 脚本是否能在真实 Cocos 3.8 类型环境编译

Editor 正式导入后应增加 Cocos/TS 编译门禁。

### 5. 117 条 QA 中 96 条标记 AUTO，但当前不是“已自动执行”

QA 元数据：
- 117 total
- P0 78 / P1 34 / P2 5
- AUTO 96 / MANUAL 11 / VISUAL 4 / PERF 6

当前 CI 没有执行这 96 条 AUTO 用例的 runtime test runner。它们是测试合同，不是已兑现自动化结果。

### 6. main 未保护，生成 workflow 直接写 main

当前 main branch protection = disabled。

以下 workflow 具有 `contents: write` 并直接 push main：
- `v4-art-generate.yml`
- `v4-runtime-generate.yml`

这意味着生成器自身的小范围检查通过后即可先写入 main，完整 V4 Quality Gates 只能事后发现问题。生产化阶段应改为：
- 生成到分支 + PR；或
- main 必须开启 required checks / branch protection。

### 7. OpenAPI 没有机器语法/引用门禁

`api/openapi-v4.yaml` 已定义 bearer auth、Idempotency-Key、ServerTime 等合同，但当前 V4 Quality Gates 只检查文件存在，不执行 OpenAPI parser / reference validation。
